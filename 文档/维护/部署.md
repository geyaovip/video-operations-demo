# GitHub与Cloudflare部署

## 当前架构

GitHub仓库：<https://github.com/geyaovip/video-operations-demo>（公开）。

前端地址：<https://video-operations-demo.pages.dev>。

纯静态Cloudflare Pages，使用Direct Upload发布；不需要也未使用新加坡云服务器。上传、生成、业务记录仍保存在访问者自己的浏览器，不会因部署自动迁移本地数据；没有新增后端、数据库、模型或平台服务。

## 发布内容

唯一源码仍是视频运营.html。构建工具在项目外临时目录生成index.html及原文件名，把内嵌媒体按内容哈希提取为独立文件，以减小首次加载；页面CSS、业务JS和初始数据结构仍内联，只有媒体URL替换。连同30个运行媒体、第三方图标许可、缓存响应头和404页上传；本地单HTML原文件不改。线上不包含文档、参考资料、原片、交付ZIP、Git目录或云凭据。

Git跟踪当前源码、文档、品牌、参考资料、短素材、配音及部署工具；媒体/原片中的大原文件仅本地保留，交付ZIP由工具重建，不进Git。素材清单仍记录54个本地正式文件，部署／无原片克隆使用runtime-only模式只核对30个必需媒体。

## 检查与发布

安装Python 3和Node.js；首次使用先通过官方Wrangler登录Cloudflare。云凭据由Wrangler管理，不放进仓库或GitHub Secrets。

```sh
python3 工具/检查交付.py --source-only --runtime-only
python3 工具/部署Cloudflare.py
```

部署脚本使用Wrangler 4.149.0，发布到video-operations-demo的main生产分支，并附上当前Git提交。当前为手动发布：git push只更新GitHub，不自动重新部署Cloudflare。

需要独立预览发布目录时：

```sh
python3 工具/构建静态站.py
```

默认在系统临时目录生成静态文件，不在项目里留下输出目录。每次发布后核验根页面、视频成片及封面、Hash详情路由、实际视频播放；Cloudflare返回成功不替代浏览器检查。

## 后续修改

先检查并提交当前源码，再推送main，最后运行部署脚本。不要把本机Wrangler OAuth或其他广泛权限令牌上传到GitHub；未来若要自动部署，单独配置专用权限及发布流程。

参考：[Cloudflare Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)、[Wrangler发布方式](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/)。
