# 开发与验收

## 工程边界

[视频运营.html](../../视频运营.html)是唯一运行源码，CSS、原生JavaScript和初始业务数据内联；固定Hash路由，无框架、构建或外置业务JSON前置。`媒体/`保持相对路径，`品牌/`保留正式原图。Python工具只用于本地检查和打包，不是运行时依赖。

本目录使用Git管理，main为当前交付分支。不要用恢复整份历史HTML覆盖用户或其他线程的新修改；先读取最新文件，做精确局部修改，保留输入、迁移、关联和真实媒体。

## 日常命令

在项目根目录启动固定来源的静态服务：

```sh
python3 -m http.server 8797 --bind 127.0.0.1
```

当前已有服务监听该端口时直接使用，不重复启动或结束用户服务。访问`http://127.0.0.1:8797/视频运营.html`；本机数据随访问来源保存。

检查源码语法、正式素材、文档链接和交付包：

```sh
python3 工具/检查交付.py --url http://127.0.0.1:8797
```

更新交付包：

```sh
python3 工具/打包交付.py
```

检查需要Python 3和Node.js；运行页面本身不需要它们。工具不上传文件、不改业务数据、不重做媒体。

## 改动检查

1. 明确受影响模块，读取产品、交互、路由和数据文档。
2. 静态语法通过后，用独立浏览器来源检查实际路径和交互，避免改写用户当前未保存输入。
3. 核验PC、900px窄屏、390px手机；必要时320px。分别检查溢出、焦点、按钮触控区、长文案、空状态及控制台。
4. 有数据行为的变更须核对保存／刷新、范围／权限、重复提交、失败及返回。生成逻辑须验证实际独立文件，不能只看动效。
5. 同步交付包并核对HTML、说明、许可和30个运行媒体文件。静态检查与ZIP一致不能代替外部平台或客户验收。
