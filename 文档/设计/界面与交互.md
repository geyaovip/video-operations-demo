# 界面与交互规范

版本：2026-10-19。适用于中文企业管理后台、内容运营工具和带AI工作区的Web产品。以视频运营当前界面为基础，作为其他项目可采用的通用规范。

## 1. 使用范围与文档分工

| 文档 | 负责内容 | 使用方式 |
| --- | --- | --- |
| 本文 | 视觉基础、组件、页面模板、通用交互与检查规则 | 跨项目复用的主体 |
| [UI复用指南](UI复用指南.md) | 可复制变量、起步样式、接入步骤及项目配置模板 | 新项目先按指南接入，再按本文补齐行为 |
| [视频运营界面规则](视频运营界面规则.md) | 当前产品入口、页面例外、实际尺寸及能力边界 | 维护视频运营时使用；其他项目不默认继承 |
| [产品需求](../产品/产品需求.md)／[研发交付说明](../技术/研发交付说明.md) | 业务范围、字段限制、状态和数据关联 | 确定具体业务，不在UI规范重复维护 |

本文使用三种口径：**基础取值**来自当前源码的有效规则；**通用约定**是后续复用应遵循的行为契约；**补充要求**用于新项目完善当前Demo未覆盖或尚未逐项验收的场景。文档不代表当前Demo已完成全部可访问性、浏览器或辅助技术验收。

通用规范不绑定单HTML、框架、接口和存储方式。视频运营的单HTML交付约束只在本项目生效。当前只定义浅色主题；深色、RTL、多语言和原生App需另做适配。

### 1.1 页面信息原则

- 首屏优先回答：现在是什么状态、用户需要处理什么、下一步在哪里。
- 一个页面只设一个主要任务；同一组连续操作只突出一个主按钮。
- 只展示帮助判断状态、完成操作或核实来源的信息；删除无意义计数、空统计、内部ID和重复状态。
- 用留白组织信息，卡片承载实际分组，不为每个字段再套一层卡片。
- 主要字段、全文、关键结果直接展示；次要历史和可选设置才折叠。
- 交互结果必须准确：已保存、已生成、已同步、已发布分别表达，不用一个“完成”掩盖不同业务阶段。
- 跨项目继承的是组件和交互契约；是否审批、审核、允许取消等由该项目业务决定。

## 3. 字体、图标与排版

### 3.1 字体与字号

基础字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。不依赖联网字体才能显示中文。正文基础14px，长文行高约1.7。

| 层级 | 字号／行高／字重 | 使用方式 |
| --- | --- | --- |
| PC页面主标题 | 24／32／600 | 每个页面一个主标题 |
| 常规手机页面标题 | 20／28／600 | 手机标题内容区；顶栏标题另见下条 |
| 手机顶栏标题 | 18／22／600 | 窄屏顶栏；小于360px可17／22 |
| 卡片、区块、弹窗标题 | 16／24／600 | 平级区块必须同规格 |
| 内容项标题 | 14／22／600 | 列表主名称、条目标题 |
| 正文 | 14／约24／400 | 说明、正文内容 |
| 控件文字 | 13／20／500 | PC普通按钮、紧凑选择控件 |
| 普通表单标签 | 13／约20／500 | 标签在输入上方；筛选标签可12／18 |
| 表格正文 | 13／约20／400 | 内容列，可按长文放宽行高 |
| 辅助信息 | 12／18／400 | 时间、提示、次要计数 |

基础层级不是“所有h1、所有button都强行相同”；顶栏、登录页和正文标题要按角色区分。不同模块的同级标题、查看全部入口必须使用相同组件，不能靠分别加margin凑齐。

手机主要文本输入通常使用16px以利阅读和避免聚焦放大；紧凑查询控件当前存在14px的项目覆盖。新项目须实际检查目标浏览器，不能把14px覆盖推广到所有手机输入。

### 3.2 对齐和文本规则

- 标题、字段、正文、列表名称左对齐；模态框主标题居中。
- 数值比较列右对齐，使用等宽数字；时间格式在同一区域保持一致。
- 左右并列卡片标题使用相同标题行高度，操作入口同一基线对齐；数量徽标不改变标题字号。
- 列表名称允许省略，详情、错误说明、待确认业务内容显示全文。被省略的名称必须有进入详情或查看完整内容的路径。
- 长URL、长账号及连续英文可断行；业务数字与单位保持语义，不用强制不换行撑宽页面。
- 0表示已知为零，`—`表示暂无值／不适用；未加载用加载态，不能先展示0误导用户。
- 不随意使用全大写、过度加粗、彩色渐变标题或装饰性副标题。

### 3.3 图标

基础图标使用一致的线性图标体系；本项目使用Tabler图标，许可随正式资产保留。通用图标18px，普通按钮内16px，密码显隐18px，询问AI手机入口图形可22px。图标大小和点击区域分开：18px图标也需要44px手机点击区。

同类操作全站用同一图标。上一页／下一页、上个月／下个月成对出现并方向对称；返回只表示返回父级，不用于切换月份。平台Logo使用正式品牌资产，不用随机通用图标替代。

纯图标按钮必须有可访问名称，必要时加悬停说明；装饰图标对辅助技术隐藏。不可见的label不能依靠鼠标hover才能知道操作含义。

## 4. 间距、布局与响应式

### 4.1 间距刻度

采用4px基础节奏，主要使用4、8、12、16、20、24、32、40、48px。当前源码存在6／7px图文间距和18px局部留白，复用时统一为语义变量，避免复制历史覆盖。

| 场景 | PC基础 | 手机基础 |
| --- | --- | --- |
| 页面左右留白 | 32px；紧凑PC20px | 16px；小于360px为12px |
| 卡片内边距 | 24px | 18px 16px |
| 卡片／网格间距 | 20px | 16px |
| 页面标题与主体 | 24px | 20px |
| 表单字段间距 | 20px | 20px，紧凑区允许16px |
| 标签至控件 | 8px | 8px |
| 同组按钮间距 | 8px | 8px |
| 图标与文字 | 6–8px | 6–8px |

先减少无意义内容，再处理空白；不靠加装饰卡或无效统计填满页面。并列摘要卡优先等宽，长内容卡不强制裁剪到同一固定高度。

### 4.2 应用框架

- PC：左侧导航＋顶部工具栏＋内容区。侧栏基础224px，收窄72px，顶栏56px。
- 页面主标题在内容区；手机进入顶栏后避免在正文重复显示同一个标题。
- 导航区可以独立滚动，品牌、空间入口和底部头像保持可达。
- 内容容器必须允许子项收缩：Grid使用`minmax(0,1fr)`，Flex子项设置`min-width:0`。
- 固定底栏要为正文预留真实高度及安全区；按钮不能覆盖最后一条内容或分页。
- 滚动归属明确：普通页面滚动整页，双栏工作区分别滚动列表和详情，弹窗只滚动内容区。

### 4.3 断点与适配

| 宽度 | 基础策略 |
| --- | --- |
| ≥1200px | 完整PC工作区；按任务选择两栏或三列卡片 |
| 960–1199px | 紧凑PC，减少左右留白；侧栏可收窄，避免挤压表单 |
| 768–959px | 平板／窄工作区，主导航改抽屉，复杂双栏按业务转分级 |
| ≤767px | 手机布局，表单主要单列，底部操作44px，复杂工作区列表→详情 |
| <360px | 窄手机，左右留白12px，操作允许换行，顶栏标题适当缩小 |

断点基于内容可用空间，不凭设备名称推测。一个组件可以有自己的更早断点：例如卡片在1280px以下减列、报告在960px以下分级，这属于项目适配，不能要求所有模块共用一个切换点。

新项目至少检查1440、1024、900、768、390、320px；验证767／768与959／960边界。内容变化时加测长名称、空值、错误、弹窗和输入法状态。此表是复用验收要求，不是本次已完成的全视口测试报告。

### 4.4 手机、键盘与安全区

- 手机主要按钮、导航项、返回／关闭、筛选入口至少44px可点击高度。
- 使用动态视口高度和安全区；输入法出现后，当前输入和提交操作不能被遮挡。
- 文本框获得焦点时滚动到可见区域，不因键盘弹起反复重置整页滚动。
- 内容区可纵向滚动，普通页面不得整体横向溢出。需要横向滑动的表格／快捷操作应限制在明确容器内。
- PC表格在手机转换为具名字段卡片；确实需要二维比较的表格才保留局部横向滚动。
- 触摸状态不能依赖hover；屏幕旋转后保持当前输入和选中记录。

## 5. 按钮和操作层级

### 5.1 按钮规格

| 类型 | 视觉与用途 |
| --- | --- |
| 主按钮 | 主色实心、白字；保存、提交、生成等当前主要动作 |
| 副按钮 | 浅灰底、深灰字、细边框；取消、查看、下载、重置等独立次要动作 |
| 轻操作 | 透明底，主色文字；行内编辑、查看全部、局部AI生成；hover浅色背景 |
| 危险副按钮 | 浅红底、红字、浅红边框；进入移除／删除确认 |
| 危险主按钮 | 危险色实心、白字；明确危险动作的最终确认 |
| 图标按钮 | 无独立实心背景与边框；返回、关闭、更多等；hover轻底色 |

普通按钮PC最小40px，手机最小44px，圆角6px，水平内边距14px，图文间距6px。按钮字重500、PC13px／20px。固定高度只用于单行常规按钮，多行内容允许增高，不能裁掉文字。

询问AI属于独立轻入口：PC星光＋文字，手机只图标，透明底、无边框和阴影，hover只变文字颜色。此例外不可套到所有副按钮。

### 5.2 状态矩阵

| 状态 | 视觉 | 行为 |
| --- | --- | --- |
| 默认 | 对应按钮类型 | 可被键盘聚焦及触发 |
| hover | 主色变深／副按钮浅底加深 | 不改变尺寸和排版 |
| pressed | 轻微变暗，当前使用brightness(.96) | 不缩放到导致周围跳动 |
| focus-visible | 2px主色轮廓、外偏移2px | 鼠标点击后不强制保留键盘轮廓 |
| disabled | 浅灰底`#F0F1F5`、灰字`#9399A7` | 真正阻止触发；必要时在附近解释原因 |
| loading | 保持按钮宽度，动效＋“保存中…”等动作文字 | 阻止重复提交，不禁用与本请求无关的浏览操作 |

loading的完整处理属于复用补充要求，不能只加一个旋转图标却仍重复发请求。禁用原因对手机也应可读，不能只放title属性。

### 5.3 操作排列

- PC页头标题左、操作右；表单主要操作靠近设置末尾或固定操作区，避免需要满页寻找。
- PC弹窗底部右对齐，副按钮在前、主按钮在后。
- 手机双操作等宽，主按钮在右；三个及以上纵排，必要时把低频操作收进更多菜单。
- 多个不同结果不强行全部做主按钮；默认动作清晰，其余为副按钮／轻操作。
- 整卡已可进入详情时，不再重复放“查看详情”按钮；卡片内有删除等独立动作时不得发生点击冒泡或嵌套交互元素。
- 不支持的动作直接隐藏或解释不可用；不放点了只提示“敬请期待”的占位按钮。

## 6. 表单与输入控件

### 6.1 表单结构

PC基础为两列、20px间距；正文、多行文本和复杂选择占整行。手机主要单列。长表单按实际任务分组，每组一个区块标题，避免在每个字段上重复业务名。

标签在控件上方，真实label关联唯一输入ID；placeholder只作示例，不能代替标签。帮助文字在控件下方，错误信息靠近对应字段。单位显示在输入后方，且可访问名称包含单位。

个人资料、资料详情等默认只读展示，由明确编辑入口进入表单；只读信息使用文字键值，不伪装成不可编辑输入框。业务要求直接操作的查询／创建工作区可以直接显示表单。

### 6.2 常用控件

| 控件 | 使用规则 |
| --- | --- |
| 短文本 | 单行信息；设置长度及空白校验；不擅自修剪有业务含义的内部空格 |
| 多行文本 | 完整文案和说明，保留换行；可纵向调整高度，禁止横向撑宽 |
| 数字输入 | 可连续输入的数量优先手输，不用几十项下拉；明确最小／最大／步长／单位 |
| 有限枚举 | 少量稳定选项用下拉、单选或分段选择；文案需求等自由表达不要硬塞成风格枚举 |
| 日期／时间 | 标签说明语义；区分提醒时间、执行时间、截止时间，不能混用 |
| Checkbox | 独立可选项或多选；点击文字也切换，保留明确勾选态 |
| Switch | 清楚的开／关偏好，文案说明开启含义；是否即时保存必须统一 |
| Slider | 音量等连续范围；显示可理解的范围或当前值，支持键盘调整 |
| 密码 | 框内右侧显隐图标，18px图形、44px点击区、透明无边框，不挤出输入边界 |

密码显隐按钮使用`type="button"`，每个输入独立控制；显示／隐藏名称、`aria-pressed`和输入类型同步。切换时不清空内容、不提交表单；输入右侧预留点击区宽度。

### 6.3 校验与提交

1. 输入时允许暂态，例如清空数字再输入；不能每次按键就强制改回默认值。
2. 提交时检查必填、去空白、长度、范围、整数、关联资源及权限；不静默截断或夹到边界。
3. 错误在对应字段显示具体原因，聚焦第一个错误；复杂保存错误用区块提示补充，不只瞬间Toast。
4. 请求期间使用提交锁，保留输入；成功以真实持久化结果为准，失败可重试。
5. 服务端字段错误回到字段，冲突提示重新核对，不能覆盖他人较新数据。
6. 保存成功后更新只读内容或返回明确父级；没有改动时可以提示“内容没有变化”，不制造新版本。

保存输入草稿与正式提交的完整性要求可不同，须由项目明确。通用规范不要求草稿也填全，但草稿自身仍需可安全保存和恢复。

### 6.4 多值标签编辑

- 已有标签自然换行，末尾紧跟“＋”添加入口；删除按钮位于每个标签内部。
- 点击添加打开小表单或弹窗，名称明确；当前标签集合在保存整个表单前只是编辑值。
- 校验空白、重复、单项长度和总数量／总长度；重复内容提示并保留原集合。
- 删除当前标签仅改变本次编辑；取消编辑恢复原保存值。
- Enter在添加输入内表示确认该标签，不能误提交外层表单；中文输入组合确认不视为提交。
- 不要求用户手工维护逗号／顿号字符串；存储可序列化，UI仍提供逐项操作。

## 7. 选择器与待选集合

### 7.1 单值选择器

PC选择器靠近触发控件展开，宽度匹配内容，视口不足时翻到上方或调整位置；不允许菜单越出视口。平板／手机可用底部面板，标题居中、关闭在右，选项触控高度至少44px；当前选择器采用48px选项。

默认聚焦已选项，键盘上下／Home／End移动，Enter／Space确认，Esc取消并回到触发点。搜索输入内的按键先遵循输入语义。当前实现超过8项显示搜索框，新项目可按检索难度调整。

单值选择提交后可关闭面板；需要反复试听／比较的控件可以保持打开，但须在项目规则明确，不一会儿自动收起、一会儿不收起。

### 7.2 多资源选择面板

- 打开时复制当前集合为待选集合，确认前不改原表单；取消／关闭恢复原集合。
- 搜索、分组、类型和分页改变展示范围，不默认清空待选项；始终显示已选数量。
- 全选必须明确“本页”还是“全部结果”，不能把未读取的记录冒充已选。
- 不可用记录显示原因并禁止采用；异步确认前重新检查权限、归属和状态。
- PC列表滚动，分页位于列表后并独立占位；底部确认区不能覆盖分页。
- 手机分组按需展开，保留完整分组导航；确认区与系统安全区避让。
- 上传是入库动作、选择是采用动作；取消采用是否保留上传文件须明确，不把两者混为一次取消。

### 7.3 分组管理

分组使用左侧导航或手机展开列表；选中态用主色浅底。搜索只缩小分组列表，不改变已选资源。新建、重命名、排序、删除入口稳定；更多操作靠近对应分组，不在远处放难以关联的按钮。

删除分组与删除内容是两个动作，确认文案说明资源去向。重名、空名、引用和权限按项目校验。拖拽排序必须有可操作的替代方式，不能仅支持鼠标拖动。

## 8. 筛选、查询与分页

### 8.1 筛选规则

复杂多条件列表区分“输入中的条件”和“已应用条件”：更改输入只暂存，查询／搜索Enter一次应用，重置清空条件并立即恢复默认列表。查询重置到第一页，保留当前空间和列表／卡片视图。

页签、类型切换、日历月份等明确的单项导航可以即时生效；这些例外应在页面规则声明。不要一半字段即时刷新、一半等查询却没有规律。

查询状态、排序、页码、每页数和滚动位置可恢复；从详情返回不能丢失列表现场。清空搜索框不等于已经查询，重置不清除资源选择器中的勾选。

### 8.2 筛选区布局

PC标签在上、控件在下，查询和重置与输入底部对齐。当前筛选卡内边距16px 18px，字段间距约16px 12px。宽度不足自然换行，不压缩按钮文字。

手机搜索框整行，其他条件按宽度单列或两列，操作按钮保持44px、两按钮等宽。没有实际筛选需求的页面不强加筛选卡。

### 8.3 分页契约

- 基础每页20条，可选10／20／50；显示总条数、每页数、当前页／总页及上一页／下一页。
- 翻页保留筛选、排序、视图和空间；改变每页数重置相应列表至第一页。
- 有数据的单页列表显示禁用翻页边界；完全空列表不放无意义分页。
- 删除导致当前页超出总页数时，回到最后有效页；不能留下空页却声称仍有数据。
- 独立列表、明细各自保存分页，不能改变一个区块导致其他区块跳页。
- 首页摘要、日历格子、固定少量配置不分页；摘要提供“全部”入口。
- 表格导出“当前页／筛选结果／完整周期”的范围必须明确，不默认只导出当前可见页。

## 9. 列表、卡片与详情

### 9.1 表格

主要名称、关键状态、业务结果、更新时间优先；不堆内部ID、重复版本、无来源指标。表头12px、正文13px，基础横向内边距16px；正文行按内容增高，不强行锁死。

状态、时间等短列避免折行；长文列允许省略并提供详情。数字列右对齐，操作列固定同一位置。行hover仅轻底色；整行可点击时给键盘等价入口，存在行内操作时使用明确交互结构，不能把整行按钮嵌套按钮。

### 9.2 卡片

卡片按名称、核心说明、状态、更新时间组织。状态独立于名称，不把一串标签放进标题。封面必须有实际用途，素材／作品卡优先给足可辨认的预览面积；图片按实际比例contain／cover，不能拉伸。

同类卡片保持封面尺寸、信息起点、状态和时间位置一致；无图使用同尺寸占位。整卡点击时去掉重复查看按钮；hover和focus规则一致。宽屏三列并非所有卡片的固定要求，按信息密度选择，手机主要单列。

### 9.3 详情与编辑

- 详情优先将主要内容和结果放在同一阅读区，避免用多个空页签拆开必读内容。
- 只有实际存在第二类内容时才显示页签；历史、多版、来源等次要内容可折叠。
- 查看与编辑字段一致，不能编辑了六项却只展示三项；空项显示“未填写”或按产品规则省略。
- 只读详情不伪装为可编辑表单。编辑进入明确模式，保存／取消对应本次输入。
- 历史版本必须明确当前版本和可操作范围；不把历史信息改写成最新值。
- 不重复放同一资源的多处下载、查看或相同导航入口。

## 10. 弹窗、抽屉与浮层

### 10.1 容器选择

| 需求 | 优先容器 |
| --- | --- |
| 简短确认、少量字段 | 普通弹窗 |
| 搜索并选择一组资源 | 有独立滚动区的选择弹窗 |
| 长期需要查看／筛选的记录 | 独立页面或双栏工作区 |
| 与当前页面并行的辅助对话 | PC侧浮工作区，手机全屏 |
| 手机主导航 | 侧抽屉 |
| 单值选项 | PC锚定菜单，手机底部面板 |

不把所有功能塞进弹窗。消息中心、复杂资料维护等持续工作区应有可恢复地址。避免嵌套多层模态框；确有二级操作时保持原输入并清晰恢复焦点。

### 10.2 结构和尺寸

基础弹窗宽560px、圆角12px；PC距离视口至少24px，手机至少16px。大资源面板按业务扩宽，但最大宽高始终受视口限制。PC最大高度`calc(100dvh - 48px)`，手机`calc(100dvh - 32px)`。

| 区域 | PC基础 | 手机基础 |
| --- | --- | --- |
| 标题栏 | 最小64px；12px 24px | 最小60px；8px 16px |
| 标题 | 16／24／600、居中 | 同PC，长标题可换行 |
| 左右操作预留 | 各40px | 各44px |
| 内容 | 8px 24px 24px | 8px 20px 20px |
| 底部操作 | 0 24px 20px | 0 20px，并避让底部安全区 |

标题栏与底部操作栏不加横线；正文只在表格、选项或输入边界需要时使用线。内容左对齐，标题居中不影响字段布局。关闭固定右侧；左侧即使无按钮也预留同等空间，不能让标题偏左。

PC底部操作右对齐、间距8px；手机双按钮等宽，三个及以上纵排。长内容只滚动内容区，标题和底部操作仍可达。使用`min-height:0`避免Flex滚动失效。

### 10.3 打开、关闭与焦点

- 打开记录触发点，阻止背景滚动，并将焦点移入弹窗；内容有明确输入任务时优先该输入，危险确认优先安全操作。
- Tab／Shift+Tab限定在当前模态范围，关闭后回到原触发点；触发点已消失时回到合理的相邻条目或页面标题。
- Esc和右上关闭的行为一致，关闭选择面板不提交待选集合。
- 表单不通过点击遮罩隐式丢弃；需要离开保护时先处理本次输入。
- 关闭进度窗口只表示关闭展示，是否终止任务由业务单独定义，不能把二者绑定。
- 使用dialog语义、可访问名称及模态标识；多个dialog不能共享同一个标题ID。

焦点陷阱、遮罩策略、背景不可交互、屏幕阅读器朗读需要按新项目具体实现验证，不能只复制弹窗HTML就认为已完成。

### 10.4 浮层优先级

内容 < 吸顶工具／页签 < 导航抽屉 < 当前模态及其选择层 < 必要的全局反馈。原生dialog的top layer要按实际浏览器行为处理，不能只比较z-index。

同一时刻优先只保留一个阻断型工作层；弹窗打开时关闭或暂停无关菜单和对话。Popover锚定触发点，碰到边缘翻转；浮层内部滚动不能带动背景穿透。

## 11. 导航、返回与未保存保护

### 11.1 路由层级

页面内返回逻辑父级：编辑→详情→列表；子资源→所属资源；设置子表单→相应设置内容。跨模块来源不改变资源所属层级，避免A返回B、B又返回A。

返回只显示左箭头并有可访问名称和悬停说明。PC在内容标题前，手机在顶栏。顶层页面没有返回；月份、上一期等时间导航使用左右切换，不占用返回语义。

从详情返回恢复空间、筛选、页码、排序、视图和滚动；详情内切页签不重写父级。浏览器前进／后退与页面内返回分开处理，不能单纯调用history.back代替全部业务返回。

### 11.2 有草稿保存能力的离开提示

统一标题“是否保存修改？”，仅两个动作：普通副按钮“不保存”、主按钮“保存”。关闭／Esc留在原页并保留输入；不另放“继续编辑”形成三选一。

| 用户选择 | 结果 |
| --- | --- |
| 保存 | 校验并真实保存，成功后去目标父级；失败留在原页并保留输入 |
| 不保存 | 放弃本轮改动后离开；不删除以前保存的草稿 |
| 关闭／Esc | 不跳页、不保存、不清空输入 |

没有草稿保存能力的页面不能放无效“保存”；可用“继续编辑／放弃修改并离开”等真实动作。普通放弃本轮输入使用普通次要样式；永久删除资源才用危险语义。现有项目特殊保护另见项目规则。

### 11.3 空间、成员与范围变化

空间入口放主导航上方，PC顶栏不重复摆同一选择器；手机通过同一抽屉进入。切换空间、成员或其他会影响数据范围的操作先处理未保存输入。

切换后重新校验记录归属和权限；异步响应带上开始时的范围／版本，仅在仍匹配时采用。一个空间的分页、选中集合、对话和配置不能自动混入另一个空间。

## 12. 异步处理、进度与反馈

### 12.1 异步状态

| 状态 | 展示与恢复 |
| --- | --- |
| 首次加载 | 保留页面结构，显示局部加载或骨架；不展示虚假的0 |
| 请求中 | 操作附近显示处理反馈及防重提交，输入保留 |
| 排队 | 显示排队／等待语义，不编造精确完成时间 |
| 执行中 | 当前步骤、进度及必要说明；有真实百分比才显示真实百分比 |
| 成功 | 明确实际完成的结果，提供查看／下载等有效后续动作 |
| 失败 | 失败原因、已保存内容及可执行恢复入口；不自动清空表单 |
| 结果未知 | 明确待核实，避免重复执行可能已成功的外部操作 |
| 无权限／资源失效 | 解释范围或权限变化，并提供可用返回路径 |

短计算尽量在结果区域原位处理，不为一次步骤跳转额外打开可关闭的进度窗。长任务若需用户继续浏览可用可关闭进度层，但必须明确关层、关页、断网的不同影响。

### 12.2 进度步骤

完成步骤为对勾，当前步骤为转圈＋当前动作，后续步骤为编号；图标以相同圆形区域承载，避免切换时错位。百分比更新不重建整个列表，否则旋转动画和焦点会被反复重置。

未知进度用循环条或转圈。展示动画不得写回真实任务状态，不得据此产生文件、回执或完成标记。视频运营的预置循环百分比属于明确的项目例外，不能复制成其他产品的真实进度逻辑。

失败、完成、关闭显示层后停止该显示层的计时和订阅；实际后台任务根据自身生命周期继续。重开窗口从真实状态恢复，不重新执行任务。

### 12.3 提示类型

| 类型 | 适用范围 |
| --- | --- |
| 字段错误 | 某一输入无效，紧邻字段并关联输入 |
| 区块提示 | 资料变更、无法保存、缺少依赖等持续影响当前操作 |
| Toast | 已保存、已复制等短反馈，不承载必须处理的错误 |
| 确认弹窗 | 高代价、不可逆或会替换重要输入的决定 |
| 消息中心／任务列表 | 离开页面后仍需追溯的结果与待处理事项 |

当前Toast约3.6秒后消失，复用时保持简短；长错误使用持续提示或详情入口。成功提示在持久化或真实回执后出现，不在按钮点击瞬间抢先显示。可访问状态通过适度的live region播报，不每秒朗读一次进度。

## 13. AI对话与嵌入式工作单

- AI是辅助工作入口，不替代正常导航和基础页面；同一项保存／权限／校验规则两处一致。
- PC侧浮工作区，手机全屏；对话标题居中，右侧新对话与关闭，标题可省略但历史选择能看到完整名称。
- 打开默认新对话；历史可搜索并按当前空间恢复。除非用户明确选择，不自动把背景资源或未保存输入作为上下文。
- 快捷操作靠近输入区，文字配图标；PC自然排列，手机横向滑动，不能压成不可读的小按钮。
- 用户气泡随内容收缩，正文和工作单左对齐；不重复显示发送方、同一标题或多层无意义边框。
- 工作单是正式表单，包含明确字段、输入状态、校验、提交中、结果和失败恢复；不能只展示“已帮你完成”的文字假装业务已保存。
- AI建议写入表单前保护用户输入；替换前核对，明确保存后才改变业务数据。
- Enter发送、Shift+Enter换行，中文输入组合确认不发送；多行工作单文本域遵循自身输入语义。
- 关闭对话不丢背景表单；当前会话输入、工作单和实际任务分别管理生命周期。
- 生成失败保留原问题和输入，可明确重试；是否重新收费、生成新任务或覆盖结果须由业务定义。

嵌入式问答卡等内层容器必须留内边距，字段、标题和移除操作保持在边框内；不允许输入框直接贴着外边框形成重复重线。

## 14. 空、异常、权限与媒体

### 14.1 空状态

区分初次无数据、查询无结果、无权限、加载失败和资源删除。初次无数据给创建入口；查询无结果给重置；失败给重试；无权限不能提示“去创建”。

空状态占满所属网格宽度并居中，基础最小高度PC200px、手机180px，不挤在第一列。不重复放页面已经明显存在的多个相同创建入口，不用无意义大插画撑高。

### 14.2 权限与资源变化

不具备功能权限时隐藏不可执行操作或展示明确只读原因；可查看但暂不可执行时使用禁用＋原因。入口隐藏不能替代提交校验。

资源已删除、文件丢失、账号停用或版本改变时，不继续展示成功动作；保留用户输入并引导重新选择／返回。网络失败和业务拒绝使用不同错误说明。

### 14.3 图片、音频与视频

封面保持纵横比，失败时使用等尺寸占位及可读说明。图片alt说明实际内容，不重复装饰文案；装饰图使用空alt。

音视频提供实际播放控件，禁止默认有声自动播放。下载按钮对应当前资源／版本，文件格式和扩展名匹配；下载成功、开始下载和文件已生成不得混用。

移除本次采用与删除库内文件分别命名。素材是否仍在库、是否被历史记录引用、取消上传／采用的后果必须明确。

## 15. 键盘、可访问性与动态效果

以下为新项目必须补验的通用要求，不据此声明当前Demo获得任何认证。

- 交互使用真实button、a、input等语义；导航是链接，动作是按钮，不使用只绑点击的div替代。
- 图标按钮有名称，表单有label，错误有关联，选中／展开／勾选状态可被辅助技术识别。
- Tab顺序跟随阅读顺序；所有关键功能能用键盘完成，焦点始终可见且不被吸顶或固定底栏遮挡。
- 弹窗限制焦点并在关闭后恢复；多重浮层优先处理最上层Esc，不能一次Esc把多个工作层全部清空。
- 动态插入的成功／错误适度播报；进度读数可以查询，但不持续打断输入。
- `prefers-reduced-motion: reduce`下关闭非必要旋转、平移和过渡；仍提供静态状态文字。
- 普通颜色／阴影过渡基线150ms，不使用闪烁、强位移、持续呼吸或每次更新重启动画。
- 放大文字、浏览器缩放和长标签下不丢操作；手机触控、屏幕阅读器和键盘须分别检查。
- 拖拽、hover、长按不是唯一入口；关键状态不能仅靠颜色或图形理解。

## 16. 通用页面模板

| 模板 | 推荐结构 | 主要注意点 |
| --- | --- | --- |
| 工作台 | 少量关键状态→待办与近期内容 | 同级卡片等宽、标题对齐；摘要不分页 |
| 业务列表 | 标题＋主操作→筛选／类型→结果→分页 | 查询状态稳定、卡片／列表字段同口径 |
| 资源详情 | 主标题→结果与主要内容→次要历史 | 有内容才放页签，不重复操作 |
| 创建／编辑 | 基础输入→资源→必要设置→保存／提交 | 主操作好找，离开保护和失败不丢输入 |
| 两步向导 | 第一步输入→第二步处理及结果 | 返回保留输入，旧异步结果不得覆盖新输入 |
| 双栏工作区 | 左列表、右详情 | PC同屏；窄屏分级并恢复列表位置 |
| 设置 | 左侧分组、右侧默认内容 | 默认选中明确；个人与团队权限分开 |
| 消息中心 | 全部／未读→类别／查询→消息→分页 | 已读不等于业务完成，跳转到具体事项 |
| 登录 | 品牌区＋登录表单 | 密码显隐不独立套框，提交与错误明确 |

## 17. 复用验收清单

| 维度 | 必须能核对的结果 |
| --- | --- |
| 视觉基础 | 同一套颜色、字号、间距、边框、圆角，无随机硬编码漂移 |
| 操作层级 | 每组一个主动作，副按钮形态一致；危险操作与放弃输入不同 |
| 表单 | 默认、输入中、错误、提交中、失败、成功、只读均有定义 |
| 列表 | 查询／重置、排序、分页、空态、详情返回位置完整 |
| 选择 | 待选与已采用分开，跨搜索／分页保留勾选，取消不改原集合 |
| 弹窗 | 标题居中，关闭固定，内容可滚，分页不被底栏覆盖 |
| 保存 | 成功以真实结果为准；失败保留输入；离开保存／不保存可解释 |
| 异步 | 不误报成功、不用动画写业务状态、重试和结果未知有恢复路径 |
| 响应式 | 规定宽度及临界点、键盘、安全区、长内容无丢失操作 |
| 可访问性 | 键盘、焦点、名称、标签、状态、对比度和减少动态效果逐项核对 |
| 范围与权限 | 无权限、空间切换、资源失效、异步过期不能误采用结果 |
| 文档维护 | 通用规则、项目例外、能力边界各有归属；未验证项不写成已通过 |

复用步骤、可复制变量及实施任务模板见[UI复用指南](UI复用指南.md)。当前视频业务例外统一见[视频运营界面规则](视频运营界面规则.md)。
